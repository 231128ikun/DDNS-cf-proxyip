# 合并与发布验收

这里记录现有程序的验收方法；不代表已经部署，也不授权生产写操作。程序和部署入口仍只有仓库现有的 `wrangler.toml` 与 `app/src/index.ts`。

## 本地与 CI

从干净工作区开始，在 `app/` 执行：

```sh
npm ci
npm run check
npm run audit:ui:main
npm run audit:parity
npm run audit:visual
```

`check` 包含类型、API 契约、单元与架构测试、构建、体积和本地 Wrangler 部署形态冒烟。导航自然高度回归随 `audit:parity` 执行，两侧采用相同小行高来复现跨平台字体差异，不降低几何容差。

严格像素命令仍会因已记录的安全差异及抗锯齿差异返回非零；按 `docs/refactor-status.md` 逐项核对，新增差异不能默认接受。严格 `audit:ui` 仍单独保留；相对 main 无新增无障碍退步不等于通过全部无障碍要求。

旧池兼容验收通过真实 `ApiClient -> Worker -> application -> KV adapter` 闭环读取旧备注、两字段、三字段和带端口 IPv6 格式，再追加未知元数据。测试检查已有元数据与备注保留、配置更新保留其他设置、不新建配置或池 key、不修改绑定与池名称。全部操作只使用内存 KV。

## 真实环境验收：尚未执行

真实环境需要独立的验收 Worker 与 KV 资源，由账户管理员按现有程序配置绑定。不可复用生产 KV、DNS 管理目标或通知接收方；不要把资源标识或密钥提交仓库。

执行前需明确允许该隔离环境的部署和写操作。完成资源准备后，验收同一个 Git 提交的构建，记录提交、构建日志和检查结果：

- 静态首页与缺失资源行为正常，`/api/health`、未知 API JSON 404 正常。
- 开启鉴权后，未认证访问、正确/错误登录、HTTPS Secure Cookie、刷新及查询密钥清理正常。
- 使用虚构配置与地址完成保存、刷新回读，确认所有写入落在验收 KV。
- 验证 A/AAAA 与 TXT、非 443 端口、可信失效与探针异常；未知结果不得产生删除 DNS 或入桶动作。
- 若授权测试 DNS 或通知，先确认专用测试域名和接收方，再验证手动与定时入口。真实失效、超时与备用探针场景分别记录。
- 确认部署平台使用静态资源绑定，前端资源与 API 为同一次构建，配置不存在时能按环境回退。

未完成上述验收时，不宣称实际 Cloudflare 环境已经通过。现有本地模拟、Wrangler 冒烟和 CI 无法证明生产权限、绑定、Cookie、KV 可见性和调度行为。

## 合并、备份与回退

合并前核实目标提交的远端 CI 为成功，独立审查没有未处理的重要问题，兼容测试通过，并明确接受的视觉差异。Git 合并本身与上线是不同操作；若 main 关联 Cloudflare 自动部署，必须先确认合并是否会立即发布。

部署前保存当前部署版本、Git 提交及相关配置；需要导出生产 KV 时由资源管理员执行，并把备份保存在仓库外的受控位置。备份包含密钥，不能上传 CI 日志或普通附件。只读 UI 验收不应执行全量维护、DNS 删除或清桶。

发现问题时先停止进一步写入，按平台已有版本记录回退 Worker 与静态资源到同一次已知构建。代码回退不会恢复 KV 或 DNS：数据恢复需单独比较写入范围，确认没有覆盖上线后的合法变更，并另行授权。不得将覆盖恢复全部 KV 当作默认回退动作。
