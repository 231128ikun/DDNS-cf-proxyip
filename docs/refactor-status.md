评估日期：2026-10-27。页面与行为基准为 `origin/main` 的 `81a41bd014c9d7ee2ec0cd50e9d43fff58c2b8f5`（2026-10-20）。当前代码位于 `codex/modular-refactor`；此前批次已推送，本轮鉴权与批量续检修复尚待完整门禁。未部署。

## 当前判断

维护结构已经成型：Worker 按契约、领域规则、用例、端口和外部适配器分层；前端、HTTP 客户端与样式源码独立。此前的门禁能证明当前实现自身可运行，不能证明前端与 main 等价。旧 UI 对齐测试仅检查源码字符串，其中还把与 main 不同的布局当成预期；这些断言已由真实浏览器对照替换。

当前已校准关键页面布局和配置、解析操作流程，仍不能宣称整站像素或全部行为一比一等价。完整覆盖范围及保留差异见下文和本地对照报告。

程序仍只有一套：Worker 入口为 `app/src/index.ts`，面板源码为 `app/web/`；同一次构建生成 Cloudflare 静态资源，页面静态文件由边缘分发，Worker 只处理 `/api/*`。静态前端的登录卡片会先调用认证状态接口，认证成功后才渲染管理页面。Git 历史中的页面只在本地验收服务器内存中渲染，不复制到产品源码或发布目录。

## 本轮校准与修复

- 恢复 main 的独立导航按钮、目标摘要、页面标题、桌面等宽两栏、左栏域名池绑定、卡片和控制台高度。窄屏解析实况保留横向滚动表格，远程加载工具保持同一行。
- 权限和管理域名编辑器恢复原有字段顺序与保存操作；新增、编辑、取消仅改变本地草稿，“保存到页面”后由统一的“保存到 KV”落库。基础配置折叠时仍可保存或还原；切换页面保留草稿。
- 编辑管理域名时，卡片维护开关与编辑草稿同步，保存草稿不会覆盖刚切换的维护状态。浏览器对照确认 main 自身存在这项覆盖缺陷；报告单独列出，重构版按用户最近的操作保存。
- 当前 DNS 与任意探测共用 `StatusOverview` 和同一组行、出口展示组件。当前 DNS 地址经现有 `ApiClient.checkBatch` 逐地址检测，A/AAAA 使用配置端口，TXT 保留逐地址端口；最多自动检测 200 个不同地址，其余记录仍展示为未检测。
- 首次 DNS 检测等待维护配置就绪；配置晚于域名绑定返回时也使用已保存的端口，端口改变后重新检测。检测和页面展示共用同一个端口值。
- 批量检测期间锁定源输入、池选择和会改写输入的操作。中断后，继续只发送未完成项，放弃保留已完成结果；完成结果按原输入顺序合并，重复项与无法识别项继续遵守原有清洗规则。
- 探针异常继续为 unknown。现有检测契约保留有效 Colo 和出口信息；添加探测结果到池输入框时保留 ASN、国家与栈。
- DNS 添加失败保留输入，成功后返回当前记录；刷新和切换目标中止旧探测，旧资源响应不能覆盖新结果。DNS 增删、刷新不再附带无关的池列表查询。
- 权限 Token 按 Zone ID／域名身份保留，删除或排序后不再按数组位置串用；唯一匹配的旧格式权限记录继续可读。
- 恢复 main 的 `AUTH_KEY`：KV 与既有 `app_config` 优先、环境变量回退；面板密钥在公开配置中只返回布尔状态。登录支持 `?key=`、Bearer、`X-Auth-Key` 和 HttpOnly Cookie，受保护 API 对失效会话返回 401，前端随即回到登录卡片。
- 手动维护通知恢复“打开管理面板”链接；空白项目地址使用当前请求来源，不额外创建配置字段或 KV key。
- 只有 Token、没有 Zone ID 或域名的旧权限行，改名或清空备注且 Token 留空时，无法可靠匹配身份就返回 400，保留原 KV、Token 和目标引用；显式填写 Token 仍能保存。
- 配置中心与运行面板共用一份配置读取；保存直接接受 PUT 确认响应，不再额外回读覆盖刚建立的新草稿。保存等待期间由原生 fieldset 完整锁定配置控件，完成后恢复编辑；首次配置读取成功前禁止启动批量检测。
- 配置、池和绑定刷新失败保留上次确认数据，提供只读重试。写入确认使旧 GET 失效，局部绑定确认不会清除整份列表的回读失败提示；按目标读取的 DNS 仍会在切换时丢弃旧数据。
- 删除前序目标并改名后，以前端草稿中的原行身份保持选中目标；该身份不进入持久化请求。目标选择框、摘要和绑定控件依据已保存配置判断有效目标，旧绑定列表只提供显示顺序。
- 绑定写入串行执行，只提交当前行的 mapping，PUT 成功后才更新确认缓存。目标变更后的失效行不可操作，服务端对失效 key 返回 400；混合提交不会部分落库，已有历史映射仍保留。
- 新建池成功后先将确认响应纳入列表，再刷新；刷新等待或失败均保持新池选择，只读重试不会再次创建池。
- 旧目标只存完整 domain、没有 prefix/baseDomain 时，保存其他配置继续保留原子域名；保存与编辑共用已有的前缀推导规则。
- 恢复原有 `app_config.settings.CONCURRENT_CHECKS` 和 `DOH_TIMEOUT`。浏览器批量与当前记录检测使用保存的并发值，默认 32、范围 1–128；Worker DoH 查询使用保存的超时，默认 5000ms、范围 1000–30000ms。配置中心恢复这两个字段及 main 的运行参数顺序，环境变量仅用于回退。
- 旧 KV 的运行参数继续可读、可保存；稀疏旧配置沿用环境回退，部分参数更新保留未提交字段。配置解析、浏览器执行边界和 DoH 适配器共用契约中的默认值及范围。
- 域名绑定与自定义池排序共用按需加载的草稿弹窗。上下箭头只改变弹窗内的顺序；取消、背景点击和 Escape 丢弃草稿，保存失败保留草稿，成功后先应用确认顺序，再刷新原资源。回读失败保留列表和顺序，只读重试不重复提交排序。默认池固定第一，垃圾桶固定最后；绑定排序只改变显示顺序。
- 排序和批量中断确认共用 `Modal` 的遮罩、焦点约束和样式；排序关闭后归还入口焦点。长名称保持完整可访问名称，展示区域省略溢出文字；长列表独立滚动，操作按钮保持可见。零或单条目提示至少需要两项。
- 停止批量检测时使待加载的排序模块失效，晚返回的分块不会与中断确认同时打开弹窗或遗留滚动锁。
- 页角 SVG 改为原生静态资源，局部渲染和悬浮动画与重构前的内联版本一致；固定路径不再占用入口 JavaScript。
- 删除重复探测展示、旧装饰、未使用样式和图标；布局、控件和颜色继续由同一份语义样式定义，没有新增运行依赖或放宽构建预算。

## 已有维护保障

接口契约测试通过真实 `ApiClient -> Worker route -> application` 覆盖逐地址请求、并发、进度和最终合并。当前解析展示也通过这个闭环测试 A/AAAA 端口、TXT 地址端口、出口元数据、检测上限、取消和只读语义。权限 Token 删除、排序及旧格式匹配有独立回归测试；失效绑定经真实客户端和 Worker 返回 400，并验证内存 KV 零写入。

运行参数回归覆盖默认值、上下限、环境回退、KV 优先、读写保留、非默认浏览器并发及取消；真实客户端到 Worker 的部分配置保存验证未提交参数保留，真实 Worker DoH 请求通过模拟计时验证保存的超时生效。

一键洗库仍是服务端用例；垃圾桶保留统一写入入口。维护通知以距上次成功通知的数量基线对比，补货采用有界探索窗口。IP 池与存储取舍见 [`ip-pool-design.md`](./ip-pool-design.md)。
